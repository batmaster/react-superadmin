# ReferenceManyInput

A form component for handling many-to-many reference relationships with automatic junction table management.

## Overview

The `ReferenceManyInput` component is designed for scenarios where you need to manage many-to-many relationships between resources. It automatically handles the creation and deletion of junction table records, making it easy to manage complex relationships.

## Basic Usage

```tsx
import { ReferenceManyInput } from '@react-superadmin/forms';

function PostForm() {
  return (
    <ReferenceManyInput
      name='tags'
      label='Tags'
      reference='tags'
      optionText='name'
      optionValue='id'
      useJunctionTable={true}
      junctionTable='post_tags'
      foreignKey='post_id'
      target='tag_id'
    />
  );
}
```

## Junction Table Management

The component automatically handles junction table operations:

- **Loading**: Fetches existing relationships from the junction table
- **Creating**: Creates new junction records when items are added
- **Deleting**: Removes junction records when items are removed
- **Error Handling**: Gracefully handles junction table errors

### Junction Table Configuration

```tsx
// Standard configuration
<ReferenceManyInput
  useJunctionTable={true}
  junctionTable="post_tags"
  foreignKey="post_id"
  target="tag_id"
/>

// Custom key names
<ReferenceManyInput
  useJunctionTable={true}
  junctionTable="post_tags"
  junctionTableKeys={{
    foreignKey: "post_id",
    target: "tag_id"
  }}
/>
```

## Item Management

### Adding Items

Items can be added through the nested `ReferenceInput` component. The component automatically:

- Validates against `maxItems` limit
- Prevents duplicate items
- Creates junction table records (if `useJunctionTable` is true)

### Removing Items

Items can be removed by:

- Clicking the remove button on individual items
- Using the "Clear All" button to remove all items

### Reordering Items

When `allowReorder` is enabled, items can be reordered using drag and drop:

## Data Provider Integration

The component integrates with data providers for fetching reference data:

```tsx
const dataProvider = {
  getList: async (resource, params) => {
    // Fetch reference data
    const response = await fetch(`/api/${resource}`, {
      method: 'POST',
      body: JSON.stringify(params),
    });
    return response.json();
  },
  create: async (resource, params) => {
    // Create junction record
    const response = await fetch(`/api/${resource}`, {
      method: 'POST',
      body: JSON.stringify(params),
    });
    return response.json();
  },
  delete: async (resource, params) => {
    // Delete junction record
    const response = await fetch(`/api/${resource}/${params.id}`, {
      method: 'DELETE',
    });
    return response.json();
  },
};
```

## Error Handling

The component handles various error scenarios:

- **Data Loading Errors**: Displays error message and retry option
- **Junction Table Errors**: Gracefully handles missing or invalid junction tables
- **Validation Errors**: Shows validation messages when appropriate
- **Network Errors**: Provides fallback behavior for network issues

## Performance Considerations

- **Lazy Loading**: Reference data is loaded only when needed
- **Debounced Search**: Search requests are debounced to reduce API calls
- **Efficient Updates**: Only necessary junction table operations are performed
- **Memory Management**: Large arrays are handled efficiently

## Best Practices

1. **Always provide `dataProvider`**: Required for fetching reference data
2. **Use appropriate `maxItems`**: Prevents performance issues with large selections
3. **Handle errors gracefully**: Implement proper error boundaries
4. **Validate junction table configuration**: Ensure table and field names are correct
5. **Use meaningful labels**: Help users understand the relationship
6. **Consider UX**: Use `showAsChips` for better visual representation

## Troubleshooting

### Common Issues

1. **Junction table not found**: Ensure the table exists and field names are correct

4. **Performance issues**: Consider using `maxItems` and optimizing data provider queries
